```text
[任务] 审查并验证 lab2 的 page_init()，保持团队已有接口与学号标记。

放置描述符时停止；没有完整空闲页时不调用 init_memmap。
[验证] 在真实 QEMU 上检查 64/128 MiB、256 MiB 截断和非法范围；保留框架测试，
不把软件地址转换与完整通用硬件内存探测混为一谈。报告只写实际观察到的分支。
```

## 4. First-Fit 分析、Best-Fit：规格与复核提示词

```text
[任务] 阅读 default_init/default_init_memmap/default_alloc_pages/default_free_pages，

[规格] Best-Fit 实现 pmm_manager 全部接口；空闲块按地址组织，分配选择所有

树/大小索引可能的收益与更新代价，不声称 Best-Fit 对所有负载都优于 First-Fit。
```

## 5. Buddy 实现：规格与复核提示词（第一份）

```text
[任务] 依据现有 ucore 的 Page 与 pmm_manager 接口，从零设计可接入内核的 Buddy
分配模块；本轮将该设计规格用于审查已合入的 buddy_system_pmm.c。
[规格] 以 2^order 页为块，按阶维护空闲链表，块按物理页号自然对齐。任意起点
和长度的初始区间拆成合法自然对齐块。申请 n>0 页向上取整，寻找更大阶并逐级
分裂；不足则返回 NULL 且状态不变。释放以原始请求 n 还原阶，通过物理页号
异或找到伙伴；仅在伙伴空闲、同阶、在范围内时合并。维护块头、各阶和全局
空闲计数的一致性，不破坏 Page 与地址转换接口。PMM=buddy 时接入该模块。
[约束] 单执行流，无需伪造并发支持；不要改动其他分配器的语义或已有测试。
```

## 7. SLUB 实现：规格与实现提示词（第一份）

```text
[任务] 为现有内核新增教学用简化 SLUB 风格对象分配器，不依赖现成实现框架。
[接口] slub_init、kmalloc(size_t)、kfree(void*)，在 pmm_init 完成后初始化。
[规格] 两层结构：底层使用当前 PMM 页分配，顶层按 16～2048 字节二次幂大小类
管理单页 slab；嵌入式页头、位图、对象计数，返回 16 字节对齐且容量至少为
请求长度的对象。缓存复用非满 slab，对象全部释放时将页面归还 PMM。
大于 2048 字节使用连续页及页头，记录原始请求页数以兼容 Buddy。零长度返回
NULL，kfree(NULL) 无操作，超大值先检查溢出，OOM 返回 NULL。仅支持合法原始
指针的一次释放，以断言发现部分误用，不宣称完整非法指针保护。
[约束] 保留 First-Fit、Best-Fit、Buddy 和原框架测试；可简化而不实现 per-CPU、
NUMA、并发锁。清楚说明采用位图并非完整 Linux SLUB，代码放入 kern/mm。
```

## 9. QEMU 页表查询：规格与调试提示词

```text
[任务] 利用本机已有、保留调试符号的 QEMU 4.1.1，通过原生 x86 GDB 和 RISC-V
GDB 同时跟踪真实内核访存。先区分宿主调试和客体调试，再定位 QEMU 源码。
[规格] 查找 accel/tcg/cputlb.c 的 TLB tag 检查及 victim 路径，跟到
target/riscv/cpu_helper.c 的 riscv_cpu_tlb_fill/get_physical_address。
构造独立数据页上的两次 ld，sfence.vma 后记录第一次 miss、Sv39 参数、循环
索引、PTE 读取、叶子/下一层分支、权限和对齐检查、物理地址及 TLB 回填。
观察第二次是否避免再次查表，读取真实 CPUTLBEntry 的 addr_read 和 addend，

[约束] 用 backtrace 区分 CPU 访问和 gdbstub 调试内存读取，不把当前顶层 1 GiB
大页映射写成实际走完三级页表。条件断点过滤地址和访问类型，脚本自动选择
端口及符号地址。保存两个 GDB 和串口原始日志，记录真实调试错误和修正。
不覆盖编译原理课程工具，不修改全局 PATH，不虚构截图或未实际观察的分支。
```

## 10. 本轮验证和迭代记录

SLUB 首轮三 PMM 编译与测试通过。MMU 脚本经历以下修正：

1. 仅按地址捕获到了 GDB 调试读内存，增加访问类型及调用路径限制；
2. Python 观察断点增加 stop() 内的地址判断，避免其他地址产生噪声；
3. 不依赖 GDB 的函数标签显示，改为实际 PC、符号和寄存器结果断言；
4. 通过回填后的 CPUTLBEntry 与宿主 RAM 数据进一步验证地址转换。
