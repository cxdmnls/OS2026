## 2. 物理内存初始化与 Page 描述符

**对应模块：** `code/kern/mm/pmm.c` 中 `page_init()`。

**整理后的实现提示词：**

> 请在现有 ucore Lab2 框架中实现 `static void page_init(void)`，只修改该函数需要完成的逻辑。使用设备树接口取得物理内存起点和长度，检查起点、零长度和加法溢出；结合框架的 DRAM 起点和物理内存管理上界计算可管理范围。正确设置 `va_pa_offset`、`npage` 和 `pages`，根据链接符号 `end` 为 Page 描述符数组留出页对齐空间。描述符数组、内核及之前已占用的内存必须保持 reserved；只把描述符数组之后、管理上界以内的完整空闲页交给当前 `pmm_manager` 的 `init_memmap()`。如果设备树范围无效、未覆盖内核或无法容纳描述符，应使用框架已有错误处理方式终止初始化；没有完整空闲页时不得传入空区间。区分物理地址、内核虚拟地址、物理页号和 Page 指针，使用项目已有地址转换和页对齐宏。完成后用 QEMU 4.1.1 启动内核，检查输出的物理内存、描述符和空闲区间，并验证 `check_alloc_page()`；不要改动不相关初始化流程。

## 3. SLUB Challenge 实现与测试

**对应模块：** `code/kern/mm/slub.c`、`slub.h`、`slub_test.c`。本模块是 Challenge，指导书标为选做；本组决定完成。

**实现提示词：**

> 请基于当前 ucore Lab2 的物理页分配接口，从零实现一个教学用 SLUB 风格对象分配器，并接入真实内核初始化流程。先检查已有类型、头文件和 PMM 接口，再确定最小实现，不要假设实验提供了 SLUB 框架。提供 `slub_init()`、`kmalloc(size_t)`、`kfree(void *)` 和 `slub_check()` 接口；底层使用 `alloc_pages()` / `free_pages()`，支持多个固定大小 cache 和超过最大 cache 的多页对象。规定并实现零长度、空指针、16 字节对齐、对象不重叠、对象内容不串扰、对象释放后复用、最后一个对象释放后归还 slab 页以及内存不足失败时状态不变。检查尺寸计算和页数取整的整数溢出；若底层分配器按伙伴块取整，释放时仍按原始页请求数调用统一 PMM 接口。不要宣称实现了 Linux 完整 SLUB 的 per-CPU、NUMA 或并发能力。测试必须通过公开分配接口验证边界尺寸、真实数据、多 slab、复用、页回收和 OOM 状态恢复；在 `pmm_init()` 完成后运行测试，并在 First-Fit、Best-Fit、Buddy 三种 PMM 下执行真实 QEMU 内核验证。

**测试提示词：**

> 请为上面的 SLUB 模块设计独立内核测试，只使用公开的 `kmalloc()` / `kfree()` 与 PMM 统计接口，不依赖内部位图或链表布局。覆盖零长度、`kfree(NULL)`、极大尺寸溢出、所有大小类边界两侧、大对象、16 字节对齐、同时存活对象不重叠、写入后逐字节读回、多 slab 分配、释放后槽位复用、不同顺序释放后空闲页数恢复，以及可表示但超过实际可用内存的请求。每组测试输出清晰的 PASS 标记，并保证测试结束不污染物理页分配器状态。然后在三个 PMM 配置下启动真实内核，记录各自的测试结果。

## 4. QEMU MMU 页表与 TLB 调试

**整理后的实现提示词：**

## 5. 迭代中发现的问题

- MMU 调试最初在 `0x1000` 处捕获到的是 GDB 检查客体内存触发的调试查询，不是 CPU 取指。通过调用栈和访问类型区分后，增加 `MMU_INST_FETCH`、M 模式等条件，只记录真实 CPU 路径。
- 宿主 GDB 的 Python 断点最初只依赖断点 condition，回调仍记录了不相关事件。将目标地址与调用者检查放进 stop 回调后，观察收敛到目标访存。
- 优化版 QEMU 中部分局部变量显示为 `<optimized out>`，且 GDB 的符号显示可能不直接打印汇编标签。改为结合可见参数、调用栈、实际 PC、ELF 符号和最终数据结果验证，不把变量不可见或行号跳转误判成页表错误。
- SLUB 的测试以真实 PMM 页数恢复作为状态不变式，并在三个分配器下验证，防止仅在某一个分配器上掩盖页数取整或释放约定问题。当前记录的测试均通过，没有把未发生的 SLUB 故障写成历史问题。

**实现提示词：**

## 7. 分配、释放与合并

**对应模块：** `buddy_alloc_pages()`、`buddy_free_pages()` 和 `buddy_validate()`。

**实现提示词：**

> `alloc_pages(n)` 应对任意非零页数工作：向上取整到目标阶，优先查找同阶块，没有时从更高阶逐层分裂；请求 3 页时实际占用 4 页。`free_pages(base, n)` 用与分配时相同的请求页数还原块阶，通过物理页号和块大小异或计算伙伴，仅在伙伴同阶、完整、空闲、对齐且未保留时合并，并继续向更高阶合并。摘除伙伴时必须同步更新阶计数和全局 `nr_free`，保证分裂、合并后的链表和计数始终一致。

## 8. Buddy System 测试与问题定位

**对应模块：** `code/tools/check_buddy.sh` 和 `buddy_check()`。

**测试提示词：**

> 先从真实分配器取得连续 32 页区域，保存原空闲链表和计数，在该区域重建独立 Buddy 状态，测试结束后恢复原状态并归还页面。连续分配两个 8 页块，检查地址相邻、按 8 页对齐和空闲页数；按顺序释放伙伴，验证合并为 16 页并继续合并为 32 页；请求 3 页，验证按 4 页块分配且释放后完整合并；请求当前空闲页数加 1，验证返回 `NULL` 且状态不变。每个阶段检查 `PG_property`、`property`、地址对齐和管理边界。合并测试曾出现块头为 32 页但 `nr_free` 为 56，定位为摘除伙伴时只更新阶计数，修复后同时更新 `free_area[order].nr_free` 和全局 `nr_free`。最终执行 `make check-buddy`，确认 QEMU 中 init、split、coalesce、非二次幂、内存不足及 `check_alloc_page() succeeded!` 全部通过，并做一次 First-Fit 回归。
